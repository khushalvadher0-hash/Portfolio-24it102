## 1. Executive Summary

In Practical 8, route-based code splitting and component-level on-demand lazy loading were introduced to optimize the initial page load time, minimize the initial JavaScript footprint transferred to the client, and defer parsing/execution of non-critical routes until the user requests them.

Using **`React.lazy()`**, dynamic ECMAScript `import()` expressions, and **`Suspense`** with a custom accessible **`PageLoader`** fallback, Vite successfully decomposed the monolithic single-bundle application into separate, independently loaded chunks:
1. **Initial Entry Bundle (`index-*.js`)**: Reduced from **287.44 kB** to **268.07 kB** (a direct **19.37 kB** reduction in initial script payload).
2. **Projects Route (`ProjectsPage-*.js`)**: Extracted into its own **17.45 kB** chunk (plus **10.86 kB** CSS).
3. **Contact Route (`Contact-*.js`)**: Extracted into its own **3.49 kB** chunk.
4. **Task Stats Modal (`TaskStatsModal-*.js`)**: Extracted into its own **3.28 kB** chunk (plus **2.71 kB** CSS), only loaded when the student clicks "📊 View Analytics".

## 3. Analysis & Architectural Mechanics

### A. What code moved into separate chunks?
- **`ProjectsPage.jsx` & `TaskManager.jsx`**: The entire Task Manager feature, including CRUD operations, authentication forms, JWT handling, and styles, is now cleanly split into `ProjectsPage-*.js`. Users landing on Home (`/`) or Contact (`/contact`) never download this code unless they navigate to `/projects`.
- **`Contact.jsx`**: Form validation logic, character counting state, and contact instructions are isolated in `Contact-*.js`.
- **`TaskStatsModal.jsx`**: Analytical calculations, priority distribution bars, and completion rates are deferred into `TaskStatsModal-*.js`, downloading only when the user explicitly triggers the analytics modal.

### B. What loads on initial page visit (`/`)?
Only the core React framework runtime, React Router core, global stylesheets, navigation bar (`NavBar`), home page (`Home`, `About`, `Skills`), and footer (`Footer`). The browser parses ~19.37 kB less JavaScript and ~10.08 kB less CSS during the critical rendering path.

### C. When do the secondary chunks download?
- When the user clicks the "Projects" navigation link, React Router matches the `/projects` path. React triggers the dynamic `import('./pages/ProjectsPage')` promise, displaying the accessible `PageLoader` fallback until the chunk finishes downloading and executing.
- When the user clicks "📊 View Analytics", React triggers `import('./TaskStatsModal')` on demand.

### D. Why total session payload may differ from initial payload
Lazy loading does **not** make total code smaller over an entire exhaustive browsing session where every single page and modal is opened. However, it delivers dramatic improvements to **Perceived Performance**, **First Contentful Paint (FCP)**, and **Time to Interactive (TTI)** because users download only what is needed for the active view.
